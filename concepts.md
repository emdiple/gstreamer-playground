# Concepts in context of GStreamer (codingin c)
## Walkthrough
The elements are GStreamer's basic construction blocks. They process the data as it flows _downstream_ from the source elements (data producers) to the sink elements (data consumers), passing through filter elements.
## Element creation
Element creation is a fundamental process in GStreamer where you instantiate the building blocks—each responsible for a specific function (such as generating, processing, or outputting media). These elements are later linked to form a pipeline that defines the flow of multimedia data.
## Pipeline creation
A pipeline is a particular type of bin, which is the element used to contain other elements. Therefore all methods which apply to bins also apply to pipelines[^1].
[^1]: All elements in GStreamer must typically be contained inside a pipeline before they can be used, because it takes care of some clocking and messaging functions.
### Linking Elements
After creating the individual elements, the next critical step is to link them so that data can flow through the pipeline. In GStreamer, you use the function gst_element_link() to connect two elements together. The first parameter you pass is the source element—the one that produces or outputs data—and the second parameter is the destination element—the one that consumes or receives that data. The order here is very important because the linking must follow the natural data flow: data must move from a source element to a sink element (or through intermediate filters)[^2].
[^2]: Additionally, it's essential to note that only elements that are part of the same bin (or pipeline) can be linked. This means you need to add all the elements to your pipeline before you attempt to link them.
## Properties
GStreamer elements are all a particular kind of GObject, which is the entity offering property facilities.

Most GStreamer elements have customizable properties: named attributes that can be modified to change the element's behavior (writable properties) or inquired to find out about the element's internal state (readable properties)[^3].
[^3]: The names and possible values of all the properties an element exposes can be found using the gst-inspect-1.0 (CLI).
## Bus
At this point it is worth introducing the GStreamer bus a bit more formally. It is the object responsible for delivering to the application the GstMessages generated by the elements, in order and to the application thread. This last point is important, because the actual streaming of media is done in another thread than the application[^4].
[^4]: Your application should always keep an eye on the bus to be notified of errors and other playback-related issues.
